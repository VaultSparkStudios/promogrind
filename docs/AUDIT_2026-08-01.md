## 1. Turn the weekly AI plan from a context-leaking offer generator into an evidence-gated decision briefing

- **Slug:** `evidence-gated-ai-action-plan`
- **Tier / axis:** fire · Artificial Intelligence / privacy / token reduction / feature depth
- **Impact / innovation / effort / priority:** 10 / 9 / 7h / 28.4
- **Why:** The current plan silently defaults an absent bankroll to $1,000, reads recent profit and active books directly from localStorage without the Advisor privacy contract, and instructs the model to produce specific sportsbook actions despite having no current verified offer observations. That can create fabricated urgency/value while spending a model call on an evidence vacuum.
- **Live evidence:** src/components/AIActionPlan.jsx reads promo_engine_v3 and pg_bankroll directly, substitutes '1000', sends activeBooks/recentProfit by default, and renders value claims. supabase/functions/ai-action-plan/index.ts defaults bankroll again and prompts for three specific sportsbook actions without an observation/evidence input. No buildAdvisorPrivacyEnvelope, terms receipt, freshness boundary, or calibration policy is present in this path.
- **L3 recipe:** L2 plus calibration-aware confidence guardrails, source invariants, usage/analysis receipts, idempotent cache keys, and complete decision-brief provenance.
- **First value:** The first user without fresh observations gets a sober verify-first plan locally, while a consented user with fresh evidence gets an auditable plan tied to what was actually observed.

## 3. Wire the dormant self-attested chain into the real terms-to-outcome workflow

- **Slug:** `workflow-decision-evidence-chain`
- **Tier / axis:** fire · innovative features / feedback loop / security / trust
- **Impact / innovation / effort / priority:** 9 / 10 / 8h / 27.1
- **Why:** PromoGrind has terms snapshots, workflows, result feedback, and a checksum chain, but they are separate islands. The chain is imported only by tests, so a real decision cannot show that the observed terms, action, skip/placement, settlement, and reflection belong to one evidence packet.
- **Live evidence:** src/lib/promoProvenance.js exports appendReceipt/verifyChain/readReceipts but no production source imports them. SmartPromoRecommender records termsDrift snapshots; ResultFeedbackCard creates and settles workflows; no shared evidence identifier or chain receipt links those surfaces. The current chain payload also lacks workflowId/event type.
- **L3 recipe:** L2 plus complete event taxonomy, privacy-preserving hashed notes, corruption receipts, migration tests, and source-enforced production wiring.
- **First value:** The first saved workflow receives a visible, locally verifiable evidence trail that grows when the operator settles or explains the decision.

## 4. Make browser storage ownership, export, deletion, and retention source-derived

- **Slug:** `source-derived-local-data-rights-registry`
- **Tier / axis:** fire · security / privacy / organization / user control
- **Impact / innovation / effort / priority:** 9 / 8 / 6h / 24
- **Why:** The data-control allowlist is handwritten while dozens of feature modules write their own keys. New operator memory can silently fall outside export/clear, and transient or entitlement state can be restored accidentally unless every key is centrally classified.
- **Live evidence:** src/lib/dataControls.js lists 22 keys and six prefixes, while live writers include pg_ai_calibration_ledger, pg_promo_integrity_ledger_v2, pg_promo_terms_receipts, pg_profit_goal, pg_expiring_promos, pg_promo_observations, pg_action_plan_cache/date, AI usage/spend caches, milestone keys, and feature cache families. No test scans source literals against the data-control classification.
- **L3 recipe:** L2 plus source-literal discovery, prefix/dynamic-key policy, retention/sensitivity metadata, excluded-state receipts, and complete adversarial restore coverage.
- **First value:** The Profile data inventory immediately reflects every durable operator datum and can no longer silently omit a new feature key.

## 5. Make every decision-critical input and action natively operable and named

- **Slug:** `decision-control-accessibility-contract`
- **Tier / axis:** high · UI / UX / accessibility / feedback quality
- **Impact / innovation / effort / priority:** 9 / 7 / 8h / 19
- **Why:** The highest-value tracker, ledger, calculator, and dashboard forms visually show labels but frequently do not associate them with controls; destructive/edit/favorite/rating actions use clickable spans or divs. Keyboard and assistive-technology users therefore cannot reliably enter or revise the evidence the product depends on.
- **Live evidence:** Live source scan finds 56 JSX label elements without htmlFor and 20 nonsemantic div/span click targets. Verified examples include Ledger edit/delete and form controls, BetTracker delete and form controls, calculator leg removals, App favorite controls, TrackingTools deletes, DashboardActionWidgets inputs, and star ratings.
- **L3 recipe:** L2 plus a structural source gate, all verified decision-critical surfaces, theme/device pixel review, and accessibility receipts.
- **First value:** A keyboard-only user can create, edit, delete, rate, and settle operator records without guessing which control has focus.

## 6. Give every mergeable operator entity one collision-resistant identity contract

- **Slug:** `canonical-entity-id-contract`
- **Tier / axis:** high · speed / organization / sync correctness / observability
- **Impact / innovation / effort / priority:** 8 / 7 / 6h / 18.7
- **Why:** Cloud/entity merge depends on IDs, yet records are created with Date.now(), Date.now()+index, and short Math.random fragments across trackers, ledger, imports, feedback, playbooks, and widgets. Same-millisecond or multi-tab/import collisions can overwrite or conflate unrelated evidence.
- **Live evidence:** Live writers in BetTracker, Ledger, DashboardActionWidgets, CSVImportModal, BonusBet AI scan, TrackingTools, PromoExpiryWidget, ResultFeedbackCard, playbooks, ProfitCertificate, LiveScanner, and trust receipts synthesize IDs independently. promograph already has a private safeUUID helper, proving the reusable primitive exists only inside one module.
- **L3 recipe:** L2 plus deterministic import IDs, monotonic fallback, source enforcement, multi-tab collision tests, and entity-type provenance.
- **First value:** New records from two tabs or a repeated import remain distinct or deliberately idempotent instead of colliding by clock tick.
